# 跨智能体协作协议

## 用途

定义子智能体之间的经验传递和协作机制，实现知识共享和协同优化。

---

## 1. 经验传递机制

### 1.1 经验文件结构

每个项目维护一个共享经验文件：

```
{PROJECT_ROOT}/outputs/lessons-learned.md
```

### 1.2 经验格式规范

```markdown
## [日期] [模块名] [智能体类型]

### 问题描述
{描述遇到的问题}

### 根本原因
{分析问题的根本原因}

### 解决方案
{描述具体的解决方案}

### 适用场景
{说明此经验适用于什么场景}

### 标签
- category: {bug|performance|security|style|architecture}
- severity: {blocker|major|minor}
- tech: {vue|spring|solidity|flutter}
```

### 1.3 经验写入规则

| 规则 | 说明 | 示例 |
|------|------|------|
| **原则性 > 数值性** | 写"为什么错"而非"改了什么值" | ✅ "避免在循环中创建对象" ❌ "把 i++ 改为 ++i" |
| **模式级 > 页面级** | 写"哪种模式容易犯这个错" | ✅ "异步操作需要错误处理" ❌ "UserList.vue 第50行加 try-catch" |
| **可迁移 > 可复制** | 其他项目也能用 | ✅ "API 调用需要 loading 状态" ❌ "使用 axios.get('/api/users')" |

## 2. 经验读取机制

### 2.1 启动时读取

每个开发/测试子智能体在启动时必须：

1. 检查 `lessons-learned.md` 是否存在
2. 读取与当前任务相关的经验（按标签过滤）
3. 应用到当前工作中

### 2.2 经验过滤规则

```markdown
# 读取当前技术栈相关的经验
Grep(pattern="tech:.*{当前技术栈}", path="{lessons-learned.md}")

# 读取当前模块相关的经验
Grep(pattern="模块名:.*{当前模块}", path="{lessons-learned.md}")

# 读取当前角色相关的经验
Grep(pattern="智能体类型:.*{当前角色}", path="{lessons-learned.md}")
```

## 3. 测试报告传递

### 3.1 报告格式

测试子智能体输出标准格式的报告：

```json
{
  "module": "{模块名}",
  "dimension": "{测试维度}",
  "round": {轮次},
  "verdict": "PASS|FAIL",
  "max_severity": "blocker|major|minor|null",
  "failures": [
    {
      "severity": "blocker|major|minor",
      "category": "{问题类别}",
      "file": "{文件路径}",
      "line": {行号},
      "reason": "{问题原因}",
      "suggestion": "{修复建议}"
    }
  ]
}
```

### 3.2 报告读取

开发子智能体在修正模式下：

1. 读取所有测试报告路径
2. 按 severity 排序（blocker > major > minor）
3. 一次性修正所有问题
4. 输出修正结果

## 4. 进度同步机制

### 4.1 进度文件

```
{PROJECT_ROOT}/outputs/progress.json
```

### 4.2 进度格式

```json
{
  "project": "{项目名}",
  "startTime": "2026-05-28T10:00:00Z",
  "lastUpdate": "2026-05-28T10:30:00Z",
  "totalModules": 10,
  "completedModules": 5,
  "inProgressModules": 2,
  "failedModules": 1,
  "modules": {
    "module01": {
      "status": "completed",
      "startTime": "2026-05-28T10:00:00Z",
      "endTime": "2026-05-28T10:15:00Z",
      "tests": {
        "functional": "PASS",
        "security": "PASS",
        "performance": "FAIL"
      }
    }
  }
}
```

### 4.3 更新规则

| 事件 | 操作 |
|------|------|
| 模块开发开始 | 更新 status 为 "in_progress"，记录 startTime |
| 模块开发完成 | 更新 status 为 "completed"，记录 endTime |
| 测试通过 | 更新对应测试维度为 "PASS" |
| 测试失败 | 更新对应测试维度为 "FAIL"，记录失败原因 |
| 修正完成 | 更新 status 为 "completed" |

## 5. 冲突解决机制

### 5.1 优先级规则

当多个报告给出冲突建议时：

| 优先级 | 维度 | 说明 |
|--------|------|------|
| 1 | **类型安全** | TypeScript 类型 > 运行时检查 |
| 2 | **功能正确性** | 业务逻辑 > 性能优化 |
| 3 | **安全性** | 安全漏洞 > 功能完整性 |
| 4 | **性能** | 性能优化 > 代码风格 |
| 5 | **代码风格** | 命名规范、格式统一 |

### 5.2 降级策略

当无法同时满足所有要求时：

1. **blocker 问题**：必须修复，不允许降级
2. **major 问题**：必须修复，允许降级为 ⚠️
3. **minor 问题**：记录技术债务，不阻塞

## 7. 智能体间通信协议

### 7.1 通信方式

| 方式 | 说明 | 适用场景 |
|------|------|---------|
| **文件传递** | 通过文件系统传递数据 | 大量数据、持久化存储 |
| **任务系统** | 通过主智能体任务调度 | 任务触发、结果返回 |
| **经验共享** | 通过 lessons-learned.md | 知识传递、最佳实践 |

### 7.2 消息格式

```json
{
  "from": "{发送方智能体ID}",
  "to": "{接收方智能体ID}",
  "type": "task|result|experience",
  "timestamp": "2026-05-28T10:00:00Z",
  "payload": {
    // 消息内容
  }
}
```

### 7.3 响应格式

```json
{
  "status": "success|error",
  "message": "{响应消息}",
  "data": {
    // 响应数据
  }
}
```
