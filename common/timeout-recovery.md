# 超时检测与恢复机制

## 超时阈值配置

| 检测项 | 阈值 | 检测频率 | 自动处理 |
|-------|------|---------|---------|
| 子Agent启动 | 60秒 | 每30秒 | 自动重启Agent |
| 子Agent执行 | 300秒 | 每60秒 | 跳过任务，继续下一批 |
| 单批次总时长 | 1800秒 | 每120秒 | 跳过当前批次 |
| 测试Agent | 300秒 | 每60秒 | 按FAIL处理，触发修正 |
| 会话有效期 | 120分钟 | 每30分钟 | 自动刷新会话 |
| 并行执行超时 | 600秒 | 每60秒 | 自动降级为串行执行 |

## 自动恢复流程

```
检测到超时
├── 子Agent超时（300秒无响应）
│   ├── 第1次：记录日志，等待30秒
│   ├── 第2次：记录日志，创建新会话
│   └── 第3次：跳过该任务，标记为⚠️降级，继续下一批
├── 测试Agent超时（300秒无响应）
│   └── 按FAIL处理，触发修正循环
├── 批次超时（1800秒）
│   └── 跳过当前批次，记录日志，继续下一批
├── 会话过期（120分钟）
│   └── 自动创建新会话，从检查点恢复
└── 并行执行超时（600秒）
    └── 自动降级为串行执行，记录日志
```

## 自动跳过规则

1. 子Agent连续3次超时 → 自动跳过该模块，标记为⚠️降级
2. 测试Agent超时 → 按FAIL处理，进入修正循环
3. 修正循环超过3轮 → 自动降级为⚠️，继续下一批
4. 批次超时 → 跳过整个批次，继续下一批
5. **所有处理全自动，不询问用户，不阻塞流程**

## 并行执行专门处理

### 并行启动超时

- 检测：子代理启动超时（60秒无响应）
- 处理：自动重试1次，重试前等待10秒
- 记录：写入日志，标记为"启动重试"

### 并行执行超时

- 检测：子代理执行超时（300秒无响应）
- 处理：按FAIL处理，触发修正循环
- 记录：写入日志，标记为"并行超时"

### 并行度降级

- 检测：并行执行超时（600秒无响应）
- 处理：自动降级为串行执行
- 记录：写入日志，标记为"并行降级"

## 动态超时调整

根据任务复杂度动态调整超时阈值：

| 任务复杂度 | 超时阈值 | 说明 |
|-----------|---------|------|
| 简单CRUD | 180秒 | 标准超时 |
| 标准业务 | 300秒 | 标准超时 |
| 复杂逻辑 | 450秒 | 延长超时 |
| 第三方集成 | 600秒 | 延长超时 |
| 实时功能 | 900秒 | 延长超时 |

## 超时恢复机制

### 自动重试

- 第1次超时：记录日志，等待30秒后重试
- 第2次超时：记录日志，创建新会话后重试
- 第3次超时：跳过该任务，标记为⚠️降级

### 会话恢复

- 会话过期：自动创建新会话，从检查点恢复
- 会话失效：从 checkpoint.json 恢复最后状态
- 会话刷新：每30分钟检查会话有效性

### 批次恢复

- 批次超时：跳过当前批次，记录日志，继续下一批
- 批次失败：记录日志，自动降级为⚠️，继续下一批
- 批次中断：从检查点恢复，继续执行
