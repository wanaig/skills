# 智能体提示词精简优化建议

## 问题分析

精简提示词可能会导致以下问题：

### 1. **关键内容丢失**

| 丢失内容 | 影响 | 重要程度 |
|---------|------|---------|
| **设计决策流程** | 子代理可能跳过设计思考 | 高 |
| **冲突处理优先级** | 修正时可能做出错误选择 | 高 |
| **经验写入原则** | 经验积累不完整 | 中 |
| **JSON报告格式** | 主代理解析失败 | 高 |
| **超时与错误处理** | 子代理卡死无法恢复 | 高 |

### 2. **质量下降风险**

- 子代理可能降低质量标准
- 子代理可能忽略特殊情况处理
- 子代理可能生成不符合规范的代码

## 优化建议

### 方案1：**分层精简策略**（推荐）

将提示词分为三层：

1. **核心层**（必须保留）：核心原则、关键流程、质量标准
2. **参考层**（可引用）：详细示例、框架说明、最佳实践
3. **扩展层**（可删除）：重复说明、冗余示例

### 方案2：**补充关键内容**

在精简过程中，需要补充以下关键内容：

#### 1. **设计决策流程**

每个子代理在执行任务前，都应该有明确的设计决策流程。

**示例**：
```
### 设计决策流程（执行前必过）

在执行任务前，先回答以下问题：
1. **这个任务的核心目标是什么？** — 明确输入和输出
2. **有哪些约束条件？** — 技术约束、业务约束、时间约束
3. **已有哪些可复用的资源？** — 搜索项目中的现有代码、工具、配置
```

#### 2. **冲突处理优先级**

当子代理收到多个建议或报告时，需要有明确的优先级判断。

**示例**：
```
**冲突处理优先级**：
- 类型安全 > 性能 > 代码风格
- 安全性 > 功能完整性 > 用户体验
- 核心功能 > 辅助功能 > 管理功能
```

#### 3. **经验写入原则**

子代理在修正问题后，需要将经验写入经验库，但需要有明确的写入原则。

**示例**：
```
**经验写入三条原则**：
1. **原则性 > 数值性**：写"为什么错"而非"改了什么值"
2. **模式级 > 页面级**：写"哪种模式容易犯这个错"
3. **可迁移 > 可复制**：下个项目完全不同内容和技术栈时，这条经验还有用吗？
```

#### 4. **JSON报告格式**

子代理的JSON报告格式需要明确，以便主代理解析。

**示例**：
```
### JSON 报告格式

PASS时：
```json
{
  "module": "{模块名}",
  "dimension": "component",
  "round": {N},
  "verdict": "PASS",
  "failures": [],
  "max_severity": null
}
```

FAIL时：
```json
{
  "module": "{模块名}",
  "dimension": "component",
  "round": {N},
  "verdict": "FAIL",
  "max_severity": "blocker",
  "failures": [
    {
      "severity": "blocker",
      "category": "{维度类别}",
      "file": "src/views/UserList.vue",
      "line": 15,
      "reason": "组件树中未声明父组件传递的必要 Props",
      "suggestion": "在父组件模板中添加缺失的 Props 绑定"
    }
  ]
}
```

#### 5. **超时与错误处理**

子代理需要有超时与错误处理机制，以防止卡死。

**示例**：
```
## 超时与错误处理

**执行时间监控**：
- 开始执行时记录开始时间
- 每完成一个文件检查后检查已用时间
- 如果已用时间超过240秒（4分钟），立即停止当前操作，返回已完成的部分

**超时自动处理**：
```
如果执行时间 > 240秒：
1. 保存当前已完成的测试结果
2. 写入部分测试报告
3. 返回部分完成的结果
4. 主Agent会根据情况决定是否继续
```
```

### 方案3：**引用公共模块**

将重复的内容提取到公共模块，子代理通过引用获取。

**示例**：
```
## 核心原则

详见 `./subagent-core.md`
详见 `./file-handling.md` — 文件处理最佳实践
```

### 方案4：**动态加载**

根据任务类型动态加载相关的内容，减少不必要的加载。

## 实施步骤

### 第1步：识别关键内容

1. 分析原始提示词，识别关键内容
2. 评估每个内容的重要程度
3. 确定哪些内容必须保留，哪些可以精简

### 第2步：补充关键内容

1. 设计决策流程
2. 冲突处理优先级
3. 经验写入原则
4. JSON报告格式
5. 超时与错误处理

### 第3步：创建公共模块

1. 提取重复内容到公共模块
2. 创建引用机制
3. 测试引用是否正常工作

### 第4步：测试验证

1. 测试精简后的提示词
2. 验证代码质量是否下降
3. 根据测试结果调整

## 总结

精简提示词的目的是提高效率，但不能以牺牲质量为代价。在精简过程中，需要：

1. **保留关键内容**：设计决策流程、冲突处理优先级、经验写入原则
2. **删除冗余内容**：重复说明、冗余示例、详细背景
3. **引用公共模块**：将重复内容提取到公共模块
4. **测试验证**：精简后需要测试验证效果

通过合理的精简策略，可以在提高效率的同时，保证代码质量。
