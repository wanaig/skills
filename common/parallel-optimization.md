# 并行度优化

## 动态并行策略

### 标准模式（默认）

- 测试Agent数量：3个（各维度一个）
- 适用场景：模块数量 >= 3

### 紧凑模式

- 测试Agent数量：2个
- 适用场景：模块数量 = 2，或上下文紧张
- 策略：合并两个维度到一个Agent

### 单批模式

- 测试Agent数量：1个
- 适用场景：模块数量 = 1，或剩余任务
- 策略：所有维度串行执行

## 并行度选择逻辑

```
remaining = len(pendingItems)
if remaining >= 3:
    parallelism = 3
elif remaining == 2:
    parallelism = 2
else:
    parallelism = 1
```

## 资源感知调整

- 检测到平台并发限制时，自动降低并行度
- 上下文紧张时，减少并行度以降低上下文累积速度

## 任务复杂度评估

根据任务特征评估复杂度，动态调整并行度：

| 特征 | 复杂度分数 | 并行度调整 |
|------|-----------|-----------|
| 简单CRUD | 1 | 标准模式 |
| 标准业务 | 2 | 标准模式 |
| 复杂逻辑 | 3 | 紧凑模式 |
| 第三方集成 | 3 | 紧凑模式 |
| 实时功能 | 4 | 单批模式 |

## 并行执行监控

### 启动监控

- 检测子代理启动超时（60秒无响应）
- 自动重试1次，重试前等待10秒
- 连续2次启动失败 → 自动降级为串行执行

### 执行监控

- 检测子代理执行超时（300秒无响应）
- 按FAIL处理，触发修正循环
- 连续3次执行超时 → 自动降级为串行执行

### 资源竞争监控

- 检测多个子代理同时访问同一文件
- 自动降低并行度，改为串行执行
- 记录日志，标记为"资源竞争降级"

## 自动降级规则

1. 子代理连续2次启动失败 → 自动降级为串行执行
2. 检测到资源竞争 → 自动降级为串行执行
3. 上下文紧张 → 自动降低并行度
4. 子代理连续3次执行超时 → 自动降级为串行执行
5. 所有处理全自动，不询问用户，不阻塞流程

## 并行度恢复机制

当系统资源恢复时，自动提升并行度：

1. 检测到系统资源充足 → 自动提升并行度
2. 检测到上下文压力降低 → 自动提升并行度
3. 连续3个批次无超时 → 自动提升并行度
4. 所有处理全自动，不询问用户，不阻塞流程
