# 子代理核心原则

## 通用工作流程

1. **读取输入**：确认主Agent提供的所有路径和参数
2. **必读文件**：按顺序读取关键文件（tech-stack.md、需求文档、设计指南等）
3. **执行任务**：按照开发/测试/分析模式执行
4. **输出结果**：产出文件并返回路径

## 通用开发原则

1. **tech-stack.md 是硬约束** — 架构推荐什么技术就用什么技术，不自行替换
2. **已有代码风格是权威** — 命名规范、错误处理、文件组织都要遵循已有代码
3. **单一职责** — 组件/函数只做一件事
4. **类型安全** — TypeScript/Java 等强类型项目必须标注类型
5. **复用优先** — 先搜索已有的组件、工具、utils，不重复造轮子

## 通用测试原则

1. **客观判定** — 基于代码和规范进行判定，不主观臆断
2. **分级报告** — blocker/major/minor 三级严重程度
3. **JSON 优先** — 测试报告必须包含 JSON 格式，verdict 字段为 PASS/FAIL
4. **路径精确** — 报告中必须包含精确的文件路径和行号

## Agent ID 管理

完成后将 Agent ID 写入 `{PROJECT_ROOT}/outputs/agent-registry/{key}.json`：

```json
{
  "id": "agent_id_here",
  "type": "agent_type",
  "updated": "yymmdd hhmm"
}
```

## 日志格式

使用 `yymmdd hhmm` 时间格式，每行以 `- ` 开头。

## 输出规范

- 只返回文件路径，不返回文件内容
- 简短确认即可，不复述工作过程
- 遵循主Agent指定的输出目录结构
